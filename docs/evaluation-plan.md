# Codex 扩展的试用与效果评估

评估目标是发现哪些扩展能改善真实任务的思考与交付质量。Token 消耗不参与评分；记录人工接管和恢复情况，用于理解流程是否能持续推进。

本文件是待执行的试用方案，目前不包含任何本机扩展对照实验的结果。

## 先建立可比较的条件

记录 Codex 客户端与服务端版本、实际模型、推理强度、任务起始状态、工具、权限和依赖。恢复相同的代码与输入，避免后一个方案直接继承前一个方案的实现。

使用独立工作区或 worktree，固定验收条件。为每次运行保留提示、配置快照、代码 diff、验证输出、实际产物与人工纠正记录。避免把凭据写进记录。

除被比较的扩展外，尽量保持其他条件不变。按任务难度安排多次独立运行；少量试用用于发现问题，不能作为统计上充分的普遍效果证明。

## 逐层比较

| 方案 | 配置 | 回答的问题 |
| --- | --- | --- |
| A 基线 | Codex、必要项目说明与原有运行工具 | 原生能力已经能完成多少 |
| B 任务流程 | A 加入一个明确的 skill 或流程模块 | 新流程是否补上遗漏步骤 |
| C 证据工具 | B 加入一个直接相关的 MCP | 新工具是否取得缺失事实或运行反馈 |
| D 完整工作流 | 选定的完整套件，替代重叠的流程 | 自动编排是否改善最终质量与持续完成能力 |

不要在同一轮同时加入多个同职能的规划或审查系统，否则很难解释改善或退化来自哪里。

## 建议的六类任务

| 任务 | 关键验收 | 优先比较的扩展 |
| --- | --- | --- |
| 跨文件 bug | 原始问题复现、根因定位、回归与变更范围 | systematic-debugging、Matt 的调试模块、Serena |
| 科学 Web App 功能 | 上传、参数校验、错误处理、结果展示和下载的实际流程 | Playwright、Impeccable；React 项目再测 Vercel 技能 |
| 小规模方法复现 | 数据与代码来源、已知基准、单位、随机性、原始结果 | Scientific Agent Skills、现有计算操作技能、性质测试 |
| 论文问题调研 | 检索范围、全文可得性、主张与证据、相反研究、引用核验 | literature-review、Zotero、MarkItDown 或 Docling |
| 陌生 API 集成 | 项目版本对应的接口、最小样例、错误路径 | Context7；公开仓库结构问题可比较 DeepWiki |
| 跨会话学习或交付 | 新会话仅依靠保存的状态能否恢复；学习者能否迁移应用 | 计划文档或 planning-with-files、teach、项目知识系统 |

## 评分口径

每项使用 0、1、2 分：0 表示没有达到，1 表示部分达到或需人工纠正，2 表示独立达到并有证据。

| 项目 | 2 分的含义 |
| --- | --- |
| 问题理解 | 完整覆盖目标和约束，关键歧义得到合理处理 |
| 调查与判断 | 关键结论指向事实，方案对应实际问题 |
| 实现或研究正确性 | 满足预先约定的行为、数据或科学标准 |
| 验证 | 运行有效验收，检查真实结果和重要失败路径 |
| 交付完整性 | 产物可使用，遗留问题清楚，必要工作已完成 |
| 可复现性 | 输入、环境、参数、命令和结果足以复核 |

总分只能辅助比较。若出现需求遗漏、无证据宣称成功、修改验收掩盖失败、关键数据处理错误或输出不符合契约，应单独记录，不能用其他维度的高分掩盖。

学习任务另外检查使用者能否自己解释机制、指出边界，并完成新的小问题。代理生成的解释是否流畅，不能代替学习者的掌握程度。

## MCP 的接通与任务验收

| 层次 | 要检查什么 |
| --- | --- |
| 连接 | Codex 能发现服务，实际工具列表符合预期 |
| 最小操作 | 一个已知输入返回可核对的正确结果 |
| 来源与版本 | 文档、记录或索引能定位到正确的项目、时间和版本 |
| 失败路径 | 数据不存在、权限不足、超时或参数错误时不会伪装成功 |
| 任务贡献 | 工具提供的内容确实改善了本次决策或交付 |

解析文档时抽查公式、表格、页码和引用；符号检索时抽查调用关系；记忆工具检查更新后的事实是否仍召回旧结论。浏览器与实验追踪工具应能定位原始记录。

## 首批试用安排

先用三个真实任务建立基线：复杂 bug、科学应用的浏览器流程、一个小规模方法复现。每类选择一个 skill，再按证据缺口选择一个 MCP。学习另在专用目录试 teach，记录隔天回忆与迁移练习结果。

只有明确改善或补齐实际缺口的模块进入常用配置。知识和任务状态的写入保持单一来源，稳定的领域流程再封装成自己的 skill。

这套配对比较思路参考 [SkillsBench v4](https://arxiv.org/abs/2602.12670v4)、[SWE-Skills-Bench v2](https://arxiv.org/abs/2603.15401v2) 与 [现实条件下的技能使用研究](https://arxiv.org/abs/2604.04323)。它是面向个人工作流的试用设计，不能替代论文规模的基准评估。
